# Program Structure Documentation

This document outlines the structure of the automated trading program, detailing the role of each file in the project.

## Overview

The application is a cryptocurrency trading client developed in Python. It features a graphical user interface (GUI) built with PySide6 for interacting with the Upbit exchange. The program is designed to manage trading activities, monitor account status, and view real-time market data. It also includes capabilities for advanced data analysis using technical indicators, with the goal of integrating machine learning models for trade prediction.

## File Breakdown

### `Main.py`
- **Role**: Main Entry Point
- **Description**: This is the executable script that launches the application. It initializes the `PySide6` application and the main window. It instantiates the UI from `Main_ui.py`, connects UI element signals (e.g., button clicks) to their corresponding logic in `function_complex.py`, and starts the `asyncio` event loop for handling asynchronous tasks like the real-time WebSocket connection.

### `Main_ui.py`
- **Role**: GUI Layout Definition
- **Description**: This file is automatically generated by the Qt User Interface Compiler from a `.ui` file (likely created in Qt Designer). It contains the `Ui_MainWindow` class, which defines the entire structure of the user interface, including all widgets like windows, tables, buttons, and text displays. It should not be edited manually, as changes would be overwritten when the `.ui` file is recompiled.

### `function.py`
- **Role**: Low-Level API Interaction Layer
- **Description**: This module contains all the fundamental functions for communicating with the Upbit REST API. It handles the creation of authenticated requests (using JWT) for private endpoints and standard requests for public endpoints. Functions in this file are responsible for actions such as placing orders, canceling orders, fetching account balances, and retrieving historical candle data. The data is typically returned as a pandas DataFrame.

### `function_complex.py`
- **Role**: Application Business Logic Layer
- **Description**: This module serves as the bridge between the high-level user interface and the low-level API functions. It implements the core logic of the application. It calls functions from `function.py` to get data, processes that data, and then populates the UI tables and displays. For example, it fetches the list of open orders and displays them in the appropriate table. It also handles user actions, such as taking a `uuid` from a selected row in the UI and calling `function.close_order()`. It defines a custom `DataFrameModel` to render pandas DataFrames in `QTableView` widgets.

### `function_real.py`
- **Role**: Real-Time Data Handling
- **Description**: This module is responsible for managing the real-time data feed from Upbit. It uses the `websockets` library to establish and maintain a connection to the Upbit WebSocket API. After authenticating, it subscribes to specific real-time data channels (e.g., the ticker for "KRW-XRP") and updates the UI with live information, such as the current trade price.

### `function_feature.py`
- **Role**: Feature Engineering for Machine Learning
- **Description**: This module is dedicated to data processing for eventual use in machine learning models. It uses the `ta` library to calculate a wide array of technical analysis indicators (e.g., RSI, Bollinger Bands, MACD, etc.) from the market data. It contains functions to apply these calculations to a DataFrame of candle data, creating a rich feature set for training a prediction model.

### `README.md`
- **Role**: Project Overview
- **Description**: Provides high-level information about the project's goals, the technology stack used, and the current development status. It serves as a starting point for understanding the purpose of the application.
